## 단계별 금지 조건

- **탐색: 변경 관련 지점과 현재 사실 확인** — `payment_failed`·`refunded`의 추가 범위나 실패 응답 방침을 선택하지 말고, 변경 대상과 작업 순서를 정한 계획을 작성하지 않는다.
- **탐색: 실패 처리 검증 범위 정리** — 재결제·중복 차감 방지의 검증 범위를 확정하지 말고, 검증 항목을 특정 변경 작업에 배정한 계획을 작성하지 않는다.
- **결정: 실패 결제 정책 확정** — 선택된 정책을 상태·주문·결제·관리자별 변경 순서나 파일별 작업 목록으로 풀어쓴 계획을 작성하지 않는다.
- **계획: 변경 범위와 순서 작성** — 계획에 적은 상태 전이, 재고 차감, 실패 정보 조회 흐름을 실제 코드나 검증 항목으로 구현하지 않는다.

## Human Gate

### Gate 1 — 결제 실패 정책

- 어느 작업 뒤인지: `탐색: 변경 관련 지점과 현재 사실 확인`
- 사람이 확인할 질문:
  - 실패 결제 상태의 범위를 어떻게 정할까요?
  - 결제 실패 API의 응답을 어떻게 정할까요?
  - `payment_failed` 주문의 재결제 처리 방침을 어떻게 정할까요?
- 승인 전에 하지 않을 것: 실패 상태 범위·실패 API 응답·재결제 처리 방침 중 어느 것도 선택하거나 확정으로 기록하지 않고, 그 선택을 전제로 상태·주문·결제 변경 계획을 작성하지 않는다.

### Gate 2 — 관리자 표시와 검증 범위

- 어느 작업 뒤인지: `탐색: 실패 처리 검증 범위 정리`
- 사람이 확인할 질문:
  - 관리자 목록에 실패 정보를 어느 범위까지 표시할지 어떻게 정할까요?
  - 테스트 범위를 어떻게 정할까요?
- 승인 전에 하지 않을 것: 관리자 실패 정보의 표시 범위와 테스트 범위 중 어느 것도 선택하거나 확정으로 기록하지 않고, 그 선택을 전제로 관리자 조회 또는 검증 계획을 작성하지 않는다.

## 멈춤 조건

사람의 응답 없이 진행할 때 아래 조건 가운데 하나가 참이면 다음 작업으로 넘어가지 않고 멈춘다.

### 정보 부족

- 판정 기준: `notes/order-status-request.md`와 `notes/next-actions.md`를 모두 확인했는데, 완료 조건의 한 항목에 대응하는 현재 동작 또는 변경 후보가 어느 문서에도 적혀 있지 않으면 참이다.
- 멈춘 뒤 남길 것:
  - 어디까지 했는지: 확인을 마친 문서와 완료 조건 항목, 찾은 관련 지점을 적는다.
  - 왜 멈췄는지: 문서에 없는 현재 동작 또는 변경 후보가 무엇인지 적는다.
  - 무엇이 있어야 재개되는지: 그 항목의 현재 동작을 확인할 수 있는 코드 위치·담당자 확인·문서 중 하나를 적는다.

### 범위 초과

- 판정 기준: 계획에 넣으려는 변경 대상이 `notes/order-status-request.md`의 완료 조건 또는 Human Gate에서 사람이 확정한 정책 중 어느 것에도 연결되지 않으면 참이다.
- 멈춘 뒤 남길 것:
  - 어디까지 했는지: 완료한 탐색·결정·계획 항목과 추가로 발견한 변경 대상을 적는다.
  - 왜 멈췄는지: 그 변경 대상이 현재 완료 조건 및 확정 정책과 연결되지 않는다는 점을 적는다.
  - 무엇이 있어야 재개되는지: 변경 대상을 요청 범위에 포함한다는 사람의 승인 또는 해당 대상을 제외해도 된다는 결정을 적는다.

### 검증 불가

- 판정 기준: 완료 조건의 한 흐름에 대해 자동 검증을 실행할 수 없고, 같은 결과를 확인할 문서화된 수동 검증 방법도 없으면 참이다.
- 멈춘 뒤 남길 것:
  - 어디까지 했는지: 실행한 검증 명령 또는 시도한 수동 확인과 그 대상 흐름을 적는다.
  - 왜 멈췄는지: 실행할 수 없었던 검증과 대체 수동 검증 방법이 없다는 사실을 적는다.
  - 무엇이 있어야 재개되는지: 실행 가능한 검증 환경·테스트 보완·수동 검증 절차 중 필요한 것을 적는다.
