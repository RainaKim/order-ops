# 주문 상태 처리 개선 — 작업 진입점

## 현재 작업

주문 상태 처리 개선의 Chapter 1 문서화 단계다. 사람의 정책 결정과 구현 전 계획은 완료되었고, 아직 `src/`·`tests/` 구현과 검증 명령 실행은 시작하지 않았다.

Codex CLI는 `AGENTS.md`와 `package.json`이 있는 저장소 root에서 시작한다. 이 기준이 있어야 이 문서와 입력 문서의 상대 경로를 같은 저장소 기준으로 해석하고, root `AGENTS.md`의 작업 규칙을 적용할 수 있다.

## 기준 문서와 역할

| 문서 | 기준 역할 |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | 모든 작업에 적용되는 절차·규칙·검증 보고 기준 |
| [요청 정리](order-status-request.md) | 요청 원문, 완료 조건, 조사 당시 확인된 사실과 초기 추정 |

| [작업 경계](task-boundary.md) | 단계별 금지 조건, Human Gate 이력, 멈춤 조건 |

| [Workflow skeleton](../docs/templates/workflow-skeleton.md) | 재사용 가능한 8개 workflow 섹션의 작성·완료 기준 |

## 읽는 순서

1. [AGENTS.md](../AGENTS.md)에서 공통 작업 규칙과 편집 전 확인 사항을 읽는다.
2. [요청 정리](order-status-request.md)에서 요청의 출처와 완료 조건을 확인한다.
3. [결정 추적](pending-decisions.md)에서 확정된 선택과 E3 추가 결정을 확인한다.
4. [작업 경계](task-boundary.md)에서 Gate 1·2 통과 이력 및 멈춤 조건을 확인한다.
5. [Workflow skeleton](../docs/templates/workflow-skeleton.md)에서 작업 단위별 작성·완료 기준을 확인한다.
6. [승인된 계획](order-status-plan.md)에서 실제 수정·제외 범위와 검증 계획을 작업 입력으로 사용한다.

## 승인된 surface 연결과 handoff

| 작업 묶음 | Primary surface | 입력 | 산출물 또는 증거 | 사람 확인 | 다음 handoff |
| --- | --- | --- | --- | --- | --- |
| 요청 접수와 기준 연결 | Desktop App | 요청 출처, [공통 규칙](../AGENTS.md), 기준 문서 | 요청 기록, 적용 규칙, 읽기 의존성 | 목표·제약·완료 조건의 정확성 및 사람 결정 필요 여부 | Codex CLI에 조사 대상·미확정 항목 전달 |
| 저장소 조사와 기준선 관찰 | Codex CLI | 요청 기록, 공통 규칙, 관련 문서·코드·테스트 | 근거가 있는 사실·가설 구분과 현재 동작 기록 | 상태 변경이 필요한 관찰의 승인 및 사실·기대 정책 분리 확인 | Desktop App에 사실·가설·현재 동작·정책 질문 전달 |
| 정책 결정과 Human Gate | Desktop App | 정책 질문, 선택지, 현재 동작 근거, 완료 조건 | 결정 상태·실제 선택 결과·보류 또는 제외 항목 | 제품 동작·범위를 바꾸는 선택의 확정 | Desktop App의 계획 작업에 확정 결정과 경계 전달 |
| 승인 가능한 변경 경계 작성 | Desktop App | 완료 조건, 확정 결정, 현재 동작, 책임 경계 | 수정·제외 범위, 완료·중단 조건 | 모든 변경의 승인 근거와 계획 밖 범위 여부 | Codex CLI에 승인 범위·책임·제외·중단 조건 전달 |
| 판정 가능한 검증 계약 작성 | Codex CLI | 승인 범위, 기존 검증 공백, 저장소의 기존 명령 | 검증 시나리오와 명령별 통과·정지 기준 | 기대 결과가 승인 정책만 반영하는지 확인 | Desktop App에 검증 계약과 미실행 상태 전달 |
| 상태 정리와 실행 인계 | Desktop App | 승인된 계획, 검증 계약, Gate 상태, 검증 실행 상태 | 현재 멈춘 지점, 다음 행동, 재개 조건, 금지된 선행 작업 | 구현 시작 허용 및 검증 상태의 정확성 | 구현 승인 시 Codex CLI에 계획·검증 계약·권한 경계 전달 |

Browser는 렌더링된 웹 화면에서만 현재 동작 또는 검증 결과를 판정해야 할 때 조사·검증 작업의 보조 surface로 사용한다. Computer Use는 CLI·Browser·구조화된 연동으로 확인할 수 없는 데스크톱 GUI 조작이 필수일 때만 보조 surface로 사용하며, 앱 접근과 민감 행동은 사람이 승인한다. Scheduled task는 수동 검증이 안정된 반복 작업의 후보일 뿐, 이 workflow의 primary surface나 최초 검증 수단으로 사용하지 않는다.

## 현재 멈춘 지점

두 Human Gate는 통과했고 결정·계획 정합, 재사용 workflow skeleton, surface 연결과 handoff가 기록되어 있다. 현재는 Chapter 1의 Lab 06 E3 완료 지점이며, 구현 전 계획은 이후 구현 단계의 입력으로 준비된 상태다.

## 바로 다음 작업

Chapter 1 흐름에서는 Lab 06 E4에서 workflow가 막으려는 실패 패턴과 현재 장치를 대조하고 Chapter 1 회고를 작성한다. 이 주문 변경을 구현할 작업으로 넘어갈 때에는 승인된 계획과 AGENTS.md의 편집 전 절차를 다시 확인한다.

향후 구현 승인이 주어진 뒤에는, 코드 수정 전에 `AGENTS.md`의 Before Editing 절차에 따라 `labs/CONVENTIONS.md`, `README.md`, `src/server.ts`를 먼저 확인하고, 이어서 요청과 연결된 기능 모듈·`src/store.ts`·관련 테스트를 확인한다. 이 확인은 승인된 계획과 검증 계약을 실제 구현 입력으로 연결하기 위한 선행 조건이다.

## 아직 하지 않을 일

- 이 문서에 요청·결정·계획의 세부 내용을 다시 복제하지 않는다.
- `src/` 또는 `tests/`를 수정하거나 구현 후 검증 명령을 실행하지 않는다.
- Lab 06 E4와 구현 승인이 완료되기 전에는 구현 전 선행 확인을 구현 착수로 간주하거나 코드 변경을 시작하지 않는다.
- 승인된 계획 밖의 정책을 새로 결정하지 않는다.
- 실제 Scheduled task를 만들거나, 수동 검증으로 안정성이 확인되지 않은 작업을 자동화하지 않는다.
