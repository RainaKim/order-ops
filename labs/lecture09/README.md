# Lab 09 — Plan-first template 만들기

## 0. 이 랩이 끝나면

- 구현 전에 읽을 파일, 바꿀 파일, 단계, 테스트, 위험, 제외 범위, 멈춤 조건을 분리합니다.
- 재사용 가능한 `docs/templates/implementation-plan.md`를 완성합니다.
- Lab 12 구현 전에 사람 승인을 받을 구조를 만듭니다.
- 예상 소요 시간은 45분입니다.

## 1. 시작 전 상태 확인

- Lab 08 Issue template과 `notes/issue-draft-l08.md`가 있어야 합니다.
- 앱 코드는 v0이며 이번 lab에서도 변경하지 않습니다.
- `docs/templates/`에는 workflow skeleton만 있어야 합니다.

## 2. 실습 목표와 산출물

| 단계 | 핵심 작업 | 결과 |
| --- | --- | --- |
| E1 | 목표와 읽을 파일, 변경할 파일을 구분합니다. | `docs/templates/implementation-plan.md` 골격 |
| E2 | 구현 단계를 작게 나누고 순서를 정합니다. | 같은 template의 `Steps` |
| E3 | 테스트, 위험, 제외 범위를 명시합니다. | `Tests`, `Risks`, `Out of Scope` |
| E4 | 승인 전 구현을 막는 중단 조건을 추가합니다. | 완성된 plan template과 완료 커밋 |

## 3. 실습

### E1. 계획 template 골격 만들기

#### 설계 질문

- 목표가 구현 방법이 아니라 관찰 가능한 결과로 적혀 있나요?
- 읽을 파일과 바꿀 파일을 왜 분리해야 하나요?

#### 실행

`docs/templates/implementation-plan.md`에 `Goal`, `Files to Change`, `Files to Read First`의 빈 구조와 작성 질문을 만듭니다.

#### 검증

- [ ] 세 필수 섹션이 있습니다.
- [ ] 각 섹션의 목적이 설명돼 있습니다.
- [ ] 특정 Issue의 파일 경로가 미리 채워져 있지 않습니다.

### E2. Steps를 작은 단계로 나누기

#### 설계 질문

- 각 단계가 하나의 검토 가능한 변화로 끝나나요?
- 정책 확인과 코드 수정을 같은 단계에 넣지 않았나요?

#### 실행

`Steps` 섹션에 순서, 입력, 종료 상태를 기록할 구조를 추가합니다.

#### 검증

- [ ] Steps 섹션이 있습니다.
- [ ] 단계마다 종료 상태를 쓰게 돼 있습니다.
- [ ] 사람 승인 전 구현하지 않는 경계가 보입니다.

### E3. Tests, Risks, Out of Scope 추가하기

#### 설계 질문

- 변경으로 깨질 수 있는 동작은 무엇인가요?
- 이번 계획에서 다루지 않을 항목을 명시했나요?

#### 실행

`Tests to Add or Update`, `Risks`, `Out of Scope` 섹션과 작성 기준을 추가합니다.

#### 검증

- [ ] 세 섹션이 모두 있습니다.
- [ ] Risks는 영향과 감지 방법을 요구합니다.
- [ ] Out of Scope는 구체적인 파일 또는 동작을 요구합니다.

### E4. Stop Conditions로 완성하기

#### 설계 질문

- 어떤 정보 부족과 범위 확장에서 멈춰야 하나요?
- 검증 실패 뒤 자동으로 더 수정하지 않아야 하는 지점은 어디인가요?

#### 실행

`Stop Conditions`를 추가하고 template 전체가 구현 전 승인에 적합한지 검토한 뒤 커밋합니다.

#### 검증

- [ ] 여덟 필수 섹션이 모두 있습니다.
- [ ] 멈춤 조건은 판정 가능한 조건을 요구합니다.
- [ ] 사람 승인 여부를 기록할 위치가 있습니다.
- [ ] 앱 코드 diff가 없습니다.

## 5. 자주 하는 실수

- template에 Lab 08 Issue의 내용을 채워 재사용할 수 없게 만듭니다.
- 읽을 파일과 바꿀 파일을 같은 목록으로 둡니다.
- Stop Conditions를 마지막 체크리스트가 아니라 구현 중 멈춤 기준으로 쓰지 않습니다.
