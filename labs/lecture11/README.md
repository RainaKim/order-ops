# Lab 11 — P2 Repo 기준 문서 세트 완성

## 0. 이 랩이 끝나면

- 지금까지 만든 정책, template, prompt, platform 설정의 배치를 점검합니다.
- 새 세션이 읽어야 할 순서를 root `AGENTS.md`에 확정합니다.
- `notes/session-handoff.md`로 다음 Chapter의 시작점을 넘깁니다.
- 예상 소요 시간은 55분입니다.

## 1. 시작 전 상태 확인

- Lab 02~10의 필수 산출물이 모두 있어야 합니다.
- `src/`, `tests/`는 v0이며 코드 변경이 없어야 합니다.
- `node labs/tools/check.mjs 10`에서 누락 파일이 없어야 합니다.

## 2. 실습 목표와 산출물

| 단계 | 핵심 작업 | 결과 |
| --- | --- | --- |
| E1 | 정책·template·prompt·GitHub 설정의 배치와 참조를 점검합니다. | 기존 기준 문서의 정합 수정 |

## 3. 실습

### E1. 기준 문서 풀세트 배치 점검

#### 설계 질문

- 각 파일이 `docs/`, `notes/`, `.github/` 위치 규약과 맞나요?
- 같은 기준이 여러 파일에 중복돼 있나요?

#### 실행

`labs/CONVENTIONS.md`와 강별 산출물 지도를 기준으로 파일 배치, 이름, 참조 링크를 점검합니다. 신규 기준은 추가하지 않습니다.

#### 검증

- [ ] 필수 산출물 경로가 강별 지도와 일치합니다.
- [ ] 깨진 상대 링크가 없습니다.
- [ ] 중복된 기준의 정본이 한 곳으로 정리됐습니다.

### E2. 새 세션 읽기 순서 검증

#### 설계 질문

- 요청 유형에 따라 먼저 읽어야 할 정책과 template이 달라지나요?
- root AGENTS가 세부 문서 전문을 복제하지 않고 연결하나요?

#### 실행

root `AGENTS.md`에 project overview, 규약, 관련 정책, 계획 template, 검증 순서를 정리하고 새 Codex 세션에서 활성 지침을 요약하게 합니다.

#### 검증

- [ ] 읽기 순서가 파일 경로와 함께 정의돼 있습니다.
- [ ] 새 세션이 핵심 규칙과 명령을 찾아냈습니다.
- [ ] AGENTS.md에 세부 문서 전문을 중복하지 않았습니다.

### E3. Plan 없이 구현하지 않는지 확인

#### 설계 질문

- 한 줄 요청을 받았을 때 어떤 문서를 먼저 만들거나 갱신해야 하나요?
- 사람 승인 전 Codex가 멈췄음을 어떻게 확인할까요?

#### 실행

Lab 12 입력을 미리 읽지 않은 새 세션에 범위가 넓은 요청을 주고, plan 단계에서 멈추게 합니다. 관찰 결과를 `notes/session-handoff.md` 초안에 기록합니다.

#### 검증

- [ ] 구현 전에 읽은 문서와 파일이 기록됐습니다.
- [ ] plan 승인 전 `src/`, `tests/` 변경이 없습니다.
- [ ] 멈춘 이유와 다음 사람 확인 항목이 기록됐습니다.

### E4. Session handoff 완성

#### 설계 질문

- 다음 세션이 다시 탐색하지 않도록 어떤 상태를 넘겨야 하나요?
- Lab 12에서 사용할 issue와 plan 연결은 어디에 남길까요?

#### 실행

`notes/session-handoff.md`에 완료, 미완료, 현재 브랜치 상태, 다음 입력, 사람 결정, 검증 결과를 채우고 커밋합니다.

#### 검증

- [ ] 다음 세션의 첫 행동이 한 문장으로 정해져 있습니다.
- [ ] Lab 12 issue와 plan template 경로가 연결돼 있습니다.
- [ ] 앱 코드가 v0로 유지됩니다.
- [ ] 이 lab의 커밋 수가 두 개 이하입니다.
