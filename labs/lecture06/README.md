# Lab 06 — P1 Workflow 스켈레톤 만들기

## 0. 이 랩이 끝나면

- 2, 4, 5강 문서 세트의 용어와 연결을 점검합니다.
- 애매한 요청을 통과시키는 8단계 workflow 템플릿을 만듭니다.
- Desktop App, CLI, Browser, Automation의 역할을 작업 흐름에 연결합니다.
- 예상 소요 시간은 55분입니다.

## 1. 시작 전 상태 확인

- `notes/`에 2, 3, 5강 산출물이 있어야 합니다.
- root `AGENTS.md`가 있어야 합니다.
- `src/`, `tests/`는 여전히 v0여야 합니다.

## 3. 실습

### E1. 문서 세트 정합 점검

#### 설계 질문

- 같은 개념을 서로 다른 이름으로 부르는 문서가 있나요?
- 다음 문서가 이전 문서의 결정과 경계를 실제로 참조하나요?

#### 실행

2, 4, 5강 산출물을 나란히 읽고 요청, 결정, 범위, 검증 용어와 링크를 점검합니다. 새 정책을 추가하지 않습니다.

#### 검증

- [ ] 깨진 파일 참조가 없습니다.
- [ ] 같은 개념의 명칭이 문서 사이에서 일치합니다.
- [ ] 확정 전 질문과 확정된 사실이 구분됩니다.

### E2. 8단계 workflow skeleton 만들기

#### 설계 질문

- 요청에서 다음 행동까지 이어지려면 어떤 정보가 빠지면 안 되나요?
- 사람의 결정과 구현 계획이 섞이지 않게 어떤 순서로 둘까요?

#### 실행

`docs/templates/workflow-skeleton.md`에 요청 원문, 현재 파악, 관련 맥락, 현재 동작, 결정 필요 사항, 수정 계획, 검증 기준, 다음 단계의 8개 섹션을 빈 템플릿으로 작성합니다.

#### 검증

- [ ] 8개 섹션이 모두 있습니다.
- [ ] 섹션마다 작성 목적을 묻는 질문이 있습니다.
- [ ] 특정 주문 요청의 완성 내용이 들어 있지 않습니다.

### E3. Codex surface 연결하기

#### 설계 질문

- 계획과 리뷰처럼 긴 맥락이 필요한 작업은 어디에서 이어볼까요?
- 반복 가능한 검증, 웹 화면 확인, 예약 실행은 각각 어느 surface가 적합한가요?

#### 실행

`notes/small-development-workflow.md`에 작업 단계, 사용할 surface, 입력, 출력, 사람 확인 지점을 표로 정리합니다. Desktop App은 계획·리뷰, CLI는 반복 검증, Browser는 GitHub나 로컬 화면, Automation은 검증된 반복 작업 후보로 분리합니다(확인 2026-08-02).

#### 검증

- [ ] Desktop App, CLI, Browser, Automation이 모두 한 번 이상 등장합니다.
- [ ] 각 surface에 입력과 출력이 있습니다.
- [ ] GUI가 필요 없는 검증을 Computer Use에 배정하지 않았습니다.
- [ ] Automation 후보에 중단 조건과 사람 확인 지점이 있습니다.

### E4. 네 패턴과 네 해법 연결하기

#### 설계 질문

- 1강의 각 실패 패턴이 어떤 산출물로 줄었나요?
- 아직 해결되지 않고 다음 Chapter로 넘어가는 문제는 무엇인가요?

#### 실행

네 패턴과 현재 문서 세트의 대응 관계를 검토하고, 필요한 최소 정합 수정만 한 뒤 지정된 산출물을 함께 커밋합니다.

#### 검증

- [ ] 네 패턴 모두 대응 산출물이 있습니다.
- [ ] `src/`, `tests/` diff가 없습니다.
- [ ] workflow skeleton과 surface 문서가 서로 참조합니다.
- [ ] 커밋 수가 이 강에서 두 개를 넘지 않습니다.

- workflow 템플릿에 특정 요청의 내용을 채워 재사용성을 없앱니다.
- surface 이름만 나열하고 입력, 출력, 사람 확인을 쓰지 않습니다.
- 문서 정합을 맞추면서 앱 코드를 함께 수정합니다.
