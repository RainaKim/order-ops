# Lab 08 — Issue template 만들기

## 0. 이 랩이 끝나면

- 완료 기준이 없는 Issue의 문제를 진단합니다.
- 아홉 개 필드를 가진 `.github/ISSUE_TEMPLATE/workflow-task.md`를 만듭니다.
- 나쁜 Issue 입력을 `notes/issue-draft-l08.md`로 변환합니다.
- 예상 소요 시간은 40분입니다.

## 1. 시작 전 상태 확인

- 정책 문서 세 개와 root `AGENTS.md` 연결이 완료돼야 합니다.
- `.github/`는 아직 없어야 합니다.
- 입력은 `labs/lecture08/inputs/bad-issue-sample.md`입니다.

## 2. 실습 목표와 산출물

| 단계 | 핵심 작업 | 결과 |
| --- | --- | --- |
| E1 | 모호한 Issue에서 작업에 필요한 정보가 무엇인지 진단합니다. | 나쁜 Issue의 누락 항목 목록 |
| E2 | 작업 가능한 Issue의 아홉 필드를 설계합니다. | `.github/ISSUE_TEMPLATE/workflow-task.md` |
| E3 | Acceptance Criteria가 판정 가능한지 점검합니다. | 같은 template의 완료 기준 |
| E4 | 제공 입력을 template 구조의 실제 초안으로 바꿉니다. | `notes/issue-draft-l08.md`와 완료 커밋 |

## 3. 실습

### E1. 나쁜 Issue 진단하기

#### 설계 질문

- 현재 동작, 기대 동작, 완료 기준 중 무엇이 빠져 있나요?
- 구현자가 임의로 결정하게 되는 항목은 무엇인가요?

#### 실행

입력 파일을 읽고 빠진 정보, 범위 확장 위험, 사람 결정이 필요한 문장을 표시합니다. 아직 template은 만들지 않습니다.

#### 검증

- [ ] 누락 정보가 세 종류 이상 분류됐습니다.
- [ ] 정책 결정이 필요한 문장이 표시됐습니다.
- [ ] 앱 코드와 `.github/`에 변화가 없습니다.

### E2. 아홉 필드 설계하기

#### 설계 질문

- 구현자가 현재와 기대를 구분하려면 어떤 필드가 필요한가요?
- 범위와 사람 결정을 분리하려면 무엇을 독립 필드로 둘까요?

#### 실행

`.github/ISSUE_TEMPLATE/workflow-task.md`에 요약, 맥락, 현재 동작, 기대 동작, 범위, 제외 범위, 완료 기준, 사람 결정 필요, 참고 자료를 입력할 빈 구조를 만듭니다.

#### 검증

- [ ] 아홉 필드가 모두 있습니다.
- [ ] 제외 범위와 사람 결정이 독립 필드입니다.
- [ ] 특정 요청의 내용이 template에 채워져 있지 않습니다.

### E3. Acceptance Criteria 점검하기

#### 설계 질문

- 각 완료 조건을 실행이나 응답으로 판정할 수 있나요?
- 정책 문서와 충돌하는 조건이 있나요?

#### 실행

template의 완료 기준 안내를 참 또는 거짓으로 판정 가능한 체크박스가 되도록 다듬습니다.

#### 검증

- [ ] 완료 기준 입력 영역이 체크박스 형식입니다.
- [ ] 상태, 응답, 테스트처럼 관찰 가능한 대상을 요구합니다.
- [ ] `잘 동작한다`처럼 판정 기준 없는 표현을 요구하지 않습니다.

### E4. 실제 Issue 초안 만들기

#### 설계 질문

- 입력에서 확인된 사실과 아직 결정할 내용을 구분했나요?
- 제외 범위가 구현 범위를 실제로 제한하나요?

#### 실행

입력 파일을 template 구조로 변환해 `notes/issue-draft-l08.md`에 저장하고 검토한 뒤 커밋합니다.

#### 검증

- [ ] 아홉 필드가 모두 채워졌거나 미정으로 표시됐습니다.
- [ ] 완료 기준이 세 개 이상 있습니다.
- [ ] 사람 결정 필요 항목이 별도로 보입니다.
- [ ] 앱 코드 diff가 없습니다.
