# Lab 01 — Codex를 써도 일이 안 줄어드는 4가지 패턴

## 0. 이 랩이 끝나면

- 설명이 사라짐, 정책을 임의로 정함, 검수 근거가 없음, 작업 자산이 남지 않음이라는 네 패턴을 구분합니다.
- 이 lab에서는 앱 코드와 실습 산출물을 변경하지 않습니다.
- Lab 02 입력물인 `labs/fixtures/lecture01-transcript.md`의 위치를 확인합니다.
- 예상 소요 시간은 45분이며 실습은 선택입니다.

## 1. 시작 전 상태 확인

- `src/`와 `tests/`는 v0 상태입니다.
- root `AGENTS.md`, `docs/`, `notes/`, `.github/`는 아직 없습니다.
- 작업 트리에 변경이 없어야 합니다.
- 시작 상태가 다르면 현재 변경을 별도 브랜치에 보존한 뒤 새 독립 저장소에서 다시 시작합니다.

## 2. 실습 목표와 산출물

| 단계 | 핵심 작업 | 결과 |
| --- | --- | --- |
| E1 선택 | 맥락이 없는 요청과 repo 구조를 제공한 요청의 답변을 비교합니다. | 관찰 결과만 확인하고 별도 파일과 코드 변경은 남기지 않습니다. |

## 3. 실습

### E1. 선택 과제 — 패턴 1 재현하기

#### 설계 질문

- 프로젝트 설명이 없는 요청에서 파일명과 현재 동작을 근거로 답할 수 있을까요?
- 같은 요청에 repo 구조를 추가하면 답변의 근거가 어떻게 달라질까요?

#### 실행

새 세션에서 `주문 상태 처리 개선해줘`만 요청하고 답변에 등장한 파일명을 기록합니다. 같은 요청에 repo 구조를 덧붙여 다시 요청하되 코드는 수정하지 말라고 경계를 둡니다.

#### 검증

- [ ] 첫 답변에 실제 repo 파일명이 등장했는지 기록했습니다.
- [ ] 두 번째 답변이 인용한 파일과 근거를 기록했습니다.
- [ ] 앱 코드와 실습 산출물 파일은 변경되지 않았습니다.
