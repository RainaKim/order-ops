# Lab 02 — 대화창 답변을 작업 자산으로 바꾸기

## 0. 이 랩이 끝나면

- 대화 로그에서 일반론을 걷어내고 확인된 사실과 추정을 분리합니다.
- 사람이 정할 질문과 다음 세션의 시작점을 파일로 남깁니다.
- `notes/order-status-request.md`, `notes/pending-decisions.md`, `notes/next-actions.md`를 만듭니다.
- 예상 소요 시간은 45분입니다.

## 1. 시작 전 상태 확인

- `labs/fixtures/lecture01-transcript.md`가 존재해야 합니다.
- `notes/`는 아직 없고 `src/`, `tests/`는 v0입니다.
- 시작 상태가 다르면 현재 변경을 별도 브랜치에 보존한 뒤 새 독립 저장소에서 다시 시작합니다.

## 2. 실습 목표와 산출물

| 단계 | 핵심 작업 | 결과 |
| --- | --- | --- |
| E1 | 일반론과 repo에서 확인 가능한 내용을 분리합니다. | `notes/order-status-request.md`의 요청 원문 |
| E2 | 코드와 테스트를 근거로 사실과 추정을 구분합니다. | 같은 파일의 확인된 사실과 추정 |
| E3 | 구현 전에 결정해야 할 질문을 정리합니다. | `notes/pending-decisions.md` |
| E4 | 다음 세션이 바로 시작할 수 있는 정보를 남깁니다. | `notes/next-actions.md`와 완료 커밋 |

## 3. 실습

### E1. 일반론 제거하기

#### 설계 질문

- 이 문장은 어느 프로젝트에도 적용되는 조언인가요?
- 이 repo의 요청 원문을 보존하려면 어떤 정보가 필요한가요?

#### 실행

transcript를 읽고 요청 원문과 repo에 직접 연결되지 않는 일반론을 분리합니다. 아직 코드는 수정하지 않습니다.

#### 검증

- [ ] `notes/order-status-request.md`에 `## 요청 원문`이 있습니다.
- [ ] 요청 원문의 의미를 바꾸지 않았습니다.
- [ ] 일반론이 확인된 사실로 섞이지 않았습니다.

### E2. 사실과 추정 태깅하기

#### 설계 질문

- 파일이나 실행 결과로 확인된 문장은 무엇인가요?
- 사실처럼 보이지만 아직 확인하지 않은 문장은 무엇인가요?

#### 실행

`src/`, `tests/`를 읽어 transcript의 주장을 확인합니다. `order-status-request.md`에 `## 확인된 사실`과 `## 추정`을 나누고 사실에는 근거 파일을 붙입니다.

#### 검증

- [ ] 두 섹션이 모두 존재합니다.
- [ ] 확인된 사실마다 근거 경로가 하나 이상 있습니다.
- [ ] 확인하지 않은 내용은 추정으로 분류했습니다.

### E3. 결정 질문 남기기

#### 설계 질문

- 코드가 아니라 사람이 정해야 하는 정책은 무엇인가요?
- 각 질문에 가능한 선택지가 두 개 이상 있나요?

#### 실행

`notes/pending-decisions.md`에 결론을 대신 쓰지 말고 결정이 필요한 질문과 선택지를 기록합니다.

#### 검증

- [ ] 결정 질문이 세 개 이상 있습니다.
- [ ] 각 질문에 선택지가 두 개 이상 있습니다.
- [ ] 아직 확정되지 않은 결론을 사실처럼 쓰지 않았습니다.

### E4. 다음 세션의 시작점 만들기

#### 설계 질문

- 다음 사람이 가장 먼저 읽어야 할 파일은 무엇인가요?
- 다음 작업의 멈춤 지점은 어디인가요?

#### 실행

`notes/next-actions.md`에 다음 작업, 먼저 읽을 파일, 사람 확인이 필요한 지점을 남기고 세 파일을 함께 검토한 뒤 지정된 메시지로 커밋합니다.

#### 검증

- [ ] 다음 작업이 세 개 이하의 작은 단위로 적혀 있습니다.
- [ ] 각 작업에 입력 파일 또는 확인 대상이 있습니다.
- [ ] `git status`에 의도하지 않은 코드 변경이 없습니다.
- [ ] 지정된 커밋이 한 개 생성됐습니다.
