# Lab 02 — 대화창 답변을 작업 자산으로 바꾸기

## 0. 이 랩이 끝나면

- 세션이 바뀌어도 유지해야 할 요청과 맥락을 대화 로그에서 추출합니다.
- 확인된 사실, 추정, 사람의 결정을 구분하고 다음 세션의 시작점을 파일로 남깁니다.
- `notes/order-status-request.md`, `notes/pending-decisions.md`, `notes/next-actions.md`를 만듭니다.
- 예상 소요 시간은 45분입니다.

## 1. 시작 전 상태 확인

- `labs/fixtures/lecture01-transcript.md`가 존재해야 합니다.
- `notes/`는 아직 없고 `src/`, `tests/`는 v0입니다.
- 시작 상태가 다르면 현재 변경을 별도 브랜치에 보존한 뒤 새 독립 저장소에서 다시 시작합니다.

## 2. 실습 목표와 산출물

| 단계 | 핵심 작업 | 결과 |
| --- | --- | --- |
| E1 | 세션별 요청에서 다음 작업에도 필요한 맥락을 추출합니다. | `notes/order-status-request.md`의 요청 원문 |
| E2 | 코드와 테스트를 근거로 사실, 추정, 대화 속 결정을 구분합니다. | 같은 파일의 확인된 사실과 추정 |
| E3 | 대화에서 결정된 것처럼 보이는 정책과 미결정 질문을 다시 확인합니다. | `notes/pending-decisions.md` |
| E4 | 다음 세션이 바로 시작할 수 있는 정보를 남깁니다. | `notes/next-actions.md`와 완료 커밋 |

## 3. 실습

### E1. 세션을 넘어갈 맥락 추출하기

#### 설계 질문

- 세션이 바뀌어도 유지되어야 하는 요청과 제약은 무엇인가요?
- 답변의 일반적인 조언과 이 repo에만 해당하는 맥락을 구분할 수 있나요?

#### 실행

transcript의 세션별 요청과 응답을 읽고 다음 작업에서도 필요한 요청 원문과 제약을 추출합니다. repo에 직접 연결되지 않는 일반론은 제외하고 아직 코드는 수정하지 않습니다.

#### 검증

- [ ] `notes/order-status-request.md`에 `## 요청 원문`이 있습니다.
- [ ] 요청 원문의 의미를 바꾸지 않았습니다.
- [ ] 세션이 바뀌면 사라질 수 있는 맥락을 요청 원문과 함께 남겼습니다.
- [ ] 일반론이 repo의 사실로 섞이지 않았습니다.

### E2. 사실, 추정, 대화 속 결정 구분하기

#### 설계 질문

- 파일이나 실행 결과로 확인된 문장은 무엇인가요?
- 답변의 추정과 대화에서 결정된 것처럼 보이는 정책은 어떻게 구분할까요?

#### 실행

`src/`, `tests/`를 읽어 transcript의 주장을 확인합니다. `order-status-request.md`에 `## 확인된 사실`과 `## 추정`을 나누고 사실에는 근거 파일을 붙입니다. 대화에서 나온 정책은 코드의 현재 동작과 섞지 말고 별도로 표시합니다.

#### 검증

- [ ] 두 섹션이 모두 존재합니다.
- [ ] 확인된 사실마다 근거 경로가 하나 이상 있습니다.
- [ ] 확인하지 않은 내용은 추정으로 분류했습니다.
- [ ] 대화에서 나온 정책을 코드로 확인된 사실처럼 기록하지 않았습니다.

### E3. 결정 질문 남기기

#### 설계 질문

- 대화에서 결정된 것처럼 보이지만 다시 확인해야 할 정책은 무엇인가요?
- 아직 결정되지 않은 질문마다 가능한 선택지가 두 개 이상 있나요?

#### 실행

대화 속 결정의 근거와 유효 범위를 검토합니다. 다음 작업의 공식 기준으로 확인되지 않은 정책은 `notes/pending-decisions.md`에 질문과 선택지로 기록합니다.

#### 검증

- [ ] 결정 질문이 세 개 이상 있습니다.
- [ ] 각 질문에 선택지가 두 개 이상 있습니다.
- [ ] 대화에 등장했다는 이유만으로 정책을 공식 기준처럼 확정하지 않았습니다.

### E4. 다음 세션의 시작점 만들기

#### 설계 질문

- 다음 사람이 가장 먼저 읽어야 할 파일은 무엇인가요?
- 다음 작업의 멈춤 지점은 어디인가요?

#### 실행

`notes/next-actions.md`에 다음 작업, 먼저 읽을 파일, 사람 확인이 필요한 지점을 남기고 세 파일을 함께 검토한 뒤 지정된 메시지로 커밋합니다.

#### 검증

- [ ] 다음 작업이 세 개 이하의 작은 단위로 적혀 있습니다.
- [ ] 각 작업에 입력 파일 또는 확인 대상이 있습니다.
- [ ] `git status`에 의도하지 않은 코드 변경이 없습니다.
- [ ] 지정된 커밋이 한 개 생성됐습니다.
